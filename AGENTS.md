# AGENTS.md

Guidance for AI coding agents and contributors. `CLAUDE.md` imports this file, and `.github/copilot-instructions.md` adds the review checklist.

## Language

- All deliverables are written in **English**: commit messages, PR/Issue titles and bodies, review comments, code comments, and documentation (`README.md`, `AGENTS.md`, etc.).
- Exceptions (keep as is): quotations, technical identifiers, generated files, and external source text. Commit messages generated by the Excavator workflow stay as the workflow produces them. Manifest `description` fields are English and follow Scoop conventions.
- Runtime messages (logs, errors) are English.
- Do not rewrite Git history to change the language of past commits.

## Overview

A personal Scoop bucket. `bucket/*.json` are the Scoop manifests and `bin/*.ps1` are PowerShell scripts. The default branch is `master`.

- `bucket/*.json`: one manifest per app. File names derive from the app name, so some contain upper-case letters (for example `ElitesRNGAuraObserver.json`); this is intentional.
- `bin/checkver.ps1`, `checkurls.ps1`, `checkhashes.ps1`, `formatjson.ps1`, `missing-checkver.ps1`, `auto-pr.ps1`: wrappers that call the script of the same name in Scoop core (`$env:SCOOP_HOME`, or `scoop prefix scoop` when unset) with `bucket/` as the target. Extra arguments are passed through to the Scoop core script.
- `bin/test.ps1`: requires Pester 5.2.0+ and BuildHelpers 2.0.1+. It runs Pester over the whole repository and exits with the number of failed tests. The root-level `Scoop-Bucket.Tests.ps1` loads Scoop core's `test/Import-Bucket-Tests.ps1`, which validates changed manifests against the Scoop schema in CI and checks repository files for style constraints (no BOM, final newline, CRLF line endings, no trailing whitespace, no tab indentation, PowerShell syntax); `.gitattributes` provides the CRLF working-tree line endings the style test needs (the index keeps LF; YAML files are exempt from the CRLF check).
- `bin/update-readme.ps1`: regenerates the `## Apps` section of `README.md` from `bucket/*.json`. It finds the `## Apps` heading by exact string match, so do not rename that heading in the README.
- Do not edit the `## Apps` section of `README.md` by hand. The script replaces everything from `## Apps` up to the next `##` heading (or the end of the file), so do not add prose to that section; keep it the last section of the README.

## Commands

```powershell
.\bin\checkver.ps1            # check versions (-Update to update)
.\bin\checkurls.ps1           # check URLs
.\bin\checkhashes.ps1         # check hashes
.\bin\formatjson.ps1          # format manifest JSON
.\bin\missing-checkver.ps1    # list manifests without checkver
.\bin\test.ps1                # Pester tests
.\bin\update-readme.ps1       # regenerate the README Apps section
```

These assume a PowerShell session where Scoop is usable (`scoop` on PATH or `SCOOP_HOME` set). Scripts in `bin/` must work on both Windows PowerShell 5.1 and PowerShell Core (CI runs `bin/test.ps1` on both).

## CI and automatic updates

- `.github/workflows/ci.yml` (Tests): on pull requests and pushes, checks out Scoop core and runs `bin/test.ps1` in two jobs, WindowsPowerShell and PowerShell Core.
- `.github/workflows/excavator.yml` (Excavator): runs every 4 hours (`20 */4 * * *`) and on demand. It runs `checkver.ps1 -Update -SkipUpdated` over all manifests, makes one `<app>: Update to version <version>` commit per updated manifest, updates the README with `update-readme.ps1`, and pushes directly to `master` (it does not open PRs). The push uses the `EXCAVATOR_SSH_KEY` secret (a Deploy Key).
- `.github/workflows/keep-alive.yml`: on the 1st of each month, re-enables workflows that were disabled for inactivity.
- Commits named `docs(readme): Apps セクションを自動更新` and `<app>: Update to version <version>` are generated automatically. Do not create such commits by hand.

## Manifest conventions

- Follow the [Scoop Schema](https://raw.githubusercontent.com/ScoopInstaller/Scoop/master/schema.json) and include `$schema`.
- Required: `version`, `description`, `homepage`, `license`, `url` (or `architecture` when 32bit and 64bit differ), and `hash`. Never omit `hash`.
- Define `checkver` and `autoupdate` so Excavator can update the manifest (the `autoupdate` URL must use `$version` consistently with what `checkver` extracts).
- Use `persist` for data to keep, `bin` to expose commands, `shortcuts` for Start Menu shortcuts, and `pre_install` / `post_install` for install-time steps.
- Examples: `bucket/ScreenRelay.json` (GitHub Releases, `persist`, `post_install`) and `bucket/jquake.json` (per-`architecture` `autoupdate`).
- After adding or changing a manifest, format it with `.\bin\formatjson.ps1`; the README Apps section is updated by `.\bin\update-readme.ps1` (Excavator also does this).

## Conventions

- Commits follow [Conventional Commits](https://www.conventionalcommits.org/); branches follow [Conventional Branch](https://conventional-branch.github.io) short form (`feat/...`, `fix/...`).
- Comments in scripts are English, and so are error messages.
- Do not commit to Renovate PRs. Never commit secrets.
